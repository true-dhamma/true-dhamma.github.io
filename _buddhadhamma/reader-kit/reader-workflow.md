# 读者润色工作流程（reader-workflow）

来源：用户 pt8u（m-review-reader-12）。本文件是常设流程，每一章、每一轮读者润色都按此执行。规范内容见 `reader-style-guide.md`，全书体例见 `revision-guide.md`，词表见 `glossary-final.csv`。

## 一、性质
- 这是中文润色：中文语言、中文佛法概念、中文格式和标点。不是审校、对比翻译或补译。
- 泰文、英文、巴利只作参照，用来避免偏离法义。
- 只改中文正文，不改图片，不改冻结项（每行拉丁词、脚注、链接、硬换行、列表、标题、Dhamma 大小写等；R027 计数自 reader-13 起解除，改按 reader-style-guide R13-1 逐处对照泰文），不碰待决项（R027/R039、Dhamma 大小写、nibbuta、说话人标记）。
- 只用用户的资料包，不上网。只在本地提交，从不推送。

## 二、两遍法（必做）
1. **第一遍（按规范改）**：依照 reader-style-guide 和用户本轮意见修改；同时复查本章上一轮所有改动，看有没有同类问题：二次翻译腔、分号误用、该加或该去的引号、英文双词、古译文言、读不懂的说法。
   - 第一遍完成后：给用户发一条消息（各类改动数、关键决定、待决项），**不发文件、不打包**。
2. **第二遍（复读回改）**：忘掉“改前→改后”的过程，只把改过的地方放回上下文重新读一遍，按同一套规范：去掉新引入的翻译腔（“二次翻译腔”），检查定义、术语前后是否一致，修正其他问题。最终交付的是第二遍结果。
   - 第二遍完成后：校验、提交，发消息并交付文件包。

## 三、改动记录
- 改动元组 `(文件, 类别, 原文, 新文, 理由[, 次数])` 写在 `p1_N.py`（第一遍）、`p2_N.py`（第二遍）；`apply.py` 从基线逐条替换，断言原文出现次数，生成 `applied.json`（编号 R12-0001…，含 pass、行号、类别）。
- 类别至少包括：翻译腔、二次翻译腔、标点、过于文言、双词、措辞、句式、对仗、巴利语处理、通行译名、概念统一、不通顺。

## 四、校验（每遍结束都跑）
- `ruby bd-audit/tools/check-kramdown.rb`：0 警告，脚注 2120/2120。
- `frozen_check.py <基线>`：各项总数不变，`latin_per_line` 无违规。
- DOM 骨架逐文件对比无差异。
- `tools/frozen_check.py <基线> --allow tools/latin-allow.json`：R027 计数只报告、不强制；拉丁词改动必须事先登记在 latin-allow.json。

## 五、交付 HTML 的必备内容
1. 逐段改动对照（暗色样式），按类别统计。
2. **第一遍改动数、第二遍复读回改数**，按类别列出（含“二次翻译腔”）。
3. **否定或部分否定用户意见的条目**：逐条引用用户原文（原样），再写理由和依据（巴利、英文、泰文或全书体例）。
4. 本轮新增或修改的全书规范（revision-guide）、读者规范（reader-style-guide）、词表条目。
5. 用户本轮原始 prompt 全文，放在默认收起的 `<details>` 中。
6. 待决事项（带选项和建议）。

## 六、交付物与 reader-kit
- 每次交付都把以下内容同步放进 `_buddhadhamma/reader-kit/`，供其他 Agent 并行：更新后的记忆／笔记（`reader-notes.md`）、指南、词表、本轮审阅 HTML、改动清单副本（`rounds/<轮次>/`）。
- 交付目录 `/workspace/buddhadhamma-deliveries/<轮次>/`：43 个 MD＋reader-kit 的 zip、暗色审阅 HTML、`SHA256SUMS`。

## 七、带“？”的用户意见
- 是建议，不是硬性要求：逐条斟酌，采纳、部分采纳或不采纳都要写明理由；不采纳的按第五节第 3 条列出。
