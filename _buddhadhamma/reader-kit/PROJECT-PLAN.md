## 四、顺序与理由

建议**按目录顺序，从头开始**：B01 → B02 → … → B21。

1. B01（前置、篇首短篇）放第一，规模小、类型杂。用它把 R13-1（佛法／佛教）和口吻规则落地，也作为全书开工的校准批次。
2. B02–B05（五蕴、六处、缘起、业）正好是术语最密集的几章，按目录本来就排在前面。先做它们，词表最先稳定，后面各章少返工。
3. B06–B09（涅槃、觉悟者、止观）术语承接前面各章，按顺序做。
4. B10–B21 依次推进；后置页面（B21）放最后。

## 五、每批工作流程与质量闸门

### 流程（与第三章相同，见 reader-workflow.md）

1. 从最新集成提交拉本批分支 `m-review-reader-Bxx`，只在本地提交，从不推送。
2. **第一遍**：按 reader-style-guide 逐段润色；把本批的跨章事项（第八节）一并处理。完成后给用户发一条中期消息（各类改动数、关键决定、待决项），**不发文件**。
3. **第二遍**：忘掉改前改后，只把改过的地方放回上下文重读，去掉二次翻译腔，核对定义和术语前后一致。
4. 校验 → 提交 → 交付：43 个 MD＋reader-kit 的 zip、暗色审阅 HTML、`SHA256SUMS`。
5. 同步 reader-kit：指南、词表、记忆笔记、`rounds/<批次>/`（改动清单、applied.json、HTML）。

### 审阅 HTML 必备内容

- 第一遍、第二遍分类计数（含“二次翻译腔”）。
- 否定或部分否定用户意见的条目：照录用户原文，再写理由和依据。
- 用户本轮原始 prompt，默认收起。
- 本批新增或修改的全书规范、读者规范、词表条目。
- 不改／暂不改的项目及依据。
- 配图问题、跨章事项、待决事项。

### 质量闸门（每批必过；第三章的经验）

| 类别 | 检查点 |
|---|---|
| 标点 | 分号只用于含逗号的长并列分句或行文中的列举；顿号与外层逗号、分号分层；一句不出现两个冒号；列表词头统一“词头：说明” |
| 引号 | 该加的加（首次提出的说法、观念内容、括注所注的句中成分），该去的去（一般陈述、中文术语后已有巴利括注） |
| 文言与古译 | 现代读者难懂的改白话；已经懂的古译和既定套语保留 |
| 二次翻译腔 | 第二遍专门查：长定语、名词化、被动句、“作为……的”、搭配不当、括号插入语 |
| 双词 | 英文近义双词只写一个中文词 |
| 巴利括注 | 只注紧挨在前的那个中文词；词头“中文（巴利）：”；括号里只放巴利；拉丁经名改中文时原拉丁词进括注 |
| 佛法／佛教 | R13-1：逐处对照泰文，佛法优先，佛教只用于宗教、历史、群体义 |
| 术语分用 | 执取／执着；修行／修习／实修；彻见三法印；常见／断见 vs 常见论／断灭论；恒常；不用“心灵”；“社区”按语境；实有／实体；相续相、威仪相、密集相；比丘们 |
| 读得懂 | 直译谚语、生僻说法改到中文读者一读就懂 |
| 结构校验 | Kramdown 0 警告；脚注 2120/2120；AIPali 3300；内链 4325；硬换行 1540；列表项 2485；逐行拉丁词无违规（用 latin-allow.json）；DOM 骨架不变；图片未动 |

## 六、串行还是并行

- **B01–B05 串行**：这几批定的是核心术语和体例，后面各章都要依赖。
- **B06 起可以 2–3 条线并行**：每个 Agent 负责不同文件，共用 reader-kit。冲突按下面的办法合并：
  1. 各批只在自己的 `rounds/<批次>/` 里写 `glossary-delta.csv`、`guide-delta.md`，不直接改共享的 `glossary-final.csv` 和 `reader-style-guide.md`。

  3. 两批对同一个词有不同决定时，不各自为政：先按已有规则判；规则没有覆盖的，列为待决事项交用户定，定了以后回改先完成的那一批。
  4. 每次集成后，由主 Agent 跑一次全书校验和术语一致性扫描（比丘们、恒常、心灵、常见／断见等）。
